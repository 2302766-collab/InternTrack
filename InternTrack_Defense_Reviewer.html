Flutter + Laravel + MySQL + Provider + Sanctum

60-Second Defense Script

InternTrack is a role-based internship monitoring system built with Flutter on the frontend and Laravel on the backend, with MySQL as the database. The Flutter app handles the user interface for students, supervisors, advisers, and admins, while the Laravel API handles authentication, validation, business logic, and database access. The frontend sends HTTP requests through Dio, and the backend returns structured JSON responses under /api/v1. Authentication is token-based using Laravel Sanctum, and the token is stored securely on the client. We used Provider and ChangeNotifier for state management, especially for authentication and shared UI state. The system includes internship profile management, daily time record tracking, logbook submission and review, notifications, reports, and adviser assignment. Based on the documented test baseline dated May 6, 2026, the project had 253 automated tests passing across frontend and backend.

System Flow

Frontend Flow

  • Screen calls a service
  • Service uses ApiClient
  • Dio sends the request to Laravel
  • Response is parsed into Flutter models
  • Provider updates state and refreshes the UI

Backend Flow

  • API route receives the request
  • Middleware checks auth and role access
  • Controller validates input and runs business logic
  • Models and services access the database
  • Laravel returns structured JSON response

Important Terms To Memorize

  • Authentication: verifies who the user is
  • Authorization: checks what the user can access
  • API: bridge between frontend and backend
  • State management: keeps changing data updated in the UI
  • Provider: state management package used in Flutter
  • Middleware: checks a request before allowing access
  • Controller: handles incoming API requests
  • Model: represents and accesses database data
  • Migration: defines database table structure
  • Sanctum: Laravel package for token-based authentication

Database Overview

Core Tables

  • roles - stores role names
  • users - stores user accounts
  • internship_profiles - student internship details
  • daily_time_records - attendance and work timing
  • log_entries - student daily internship logs

Supporting Tables

  • attachments - proof files for logs
  • log_actions - review history like approval or rejection
  • notifications - in-app notifications
  • personal_access_tokens - Sanctum login tokens

Key Flows To Explain Well

  • Login flow: user submits credentials, Laravel validates, token is returned, Flutter stores it, then redirects by role.
  • Internship profile flow: student creates a profile, selects a supervisor, and the system stores the internship details.
  • DTR flow: student records time in, lunch out, lunch in, and time out, while the backend computes work minutes and status.
  • Logbook flow: student submits a log, supervisor reviews it, and the system records the decision and sends notification or email.
  • Admin flow: admin views dashboard data, student lists, and assigns advisers to students.

Common Panel Questions And Suggested Answers

What is the tech stack of your project? Our project uses Flutter and Dart for the frontend, Laravel and PHP for the backend, MySQL for the database, Dio for API communication, Provider for state management, and Laravel Sanctum for authentication.
What is authentication and how is it used here? Authentication is the process of verifying who the user is. In our system it is used in login, logout, token storage, and fetching the current user profile through secured API endpoints.
What is authorization? Authorization determines what an authenticated user is allowed to access. In our project, this is role-based, so students, supervisors, advisers, and admins see different screens and API endpoints.
How does the frontend communicate with the backend? The frontend uses Dio to send HTTP requests to Laravel API endpoints under /api/v1. Laravel processes the request and returns JSON, which Flutter converts into models for display.
What is state management in your app? State management is how the app stores data that changes and keeps the UI updated. We use Provider and ChangeNotifier, especially through AuthProvider and AdviserManagementProvider.
Why did you choose Flutter? Flutter gives a single codebase for the client side, fast UI development, and a consistent widget-based structure that is well suited for role-based dashboards and forms.
Why did you choose Laravel? Laravel provides clean routing, strong validation, middleware, ORM relationships, token authentication, and strong testing support, which made backend development more organized and secure.
How does login work in your system? The user enters email and password, Flutter sends the credentials to the login endpoint, Laravel validates them, creates a Sanctum token, and returns the token and user role. Flutter stores the token securely and redirects the user to the correct dashboard.
How is security handled? We use Sanctum tokens, role middleware, secure token storage, input sanitization, security headers, request tracing, and validation rules to protect the system.
How did you test the project? Based on the current testing baseline, we had 175 Laravel backend tests and 78 Flutter frontend tests passing, for a total of 253 automated tests.
